# 领航员：先推荐，再补充

## 输入与行为

个性化推荐需要生源省份、报考年份、省内位次、三门选科，以及用户同意使用画像。界面默认年份为 2026，用户可以修改。分数、意向省份/城市、专业、院校、预算、位次口径和批次均可后补。画像允许保存草稿，推荐任务只追问缺少的必需项。

领航员抽屉提供最少信息表单和折叠的偏好区域。点击“先看推荐”后，直接在抽屉展示已校验的院校专业方向、依据和待核对条件。没有地域、院校或专业偏好时，先给出可比较的方向与利弊，不要求用户先决定目标。完整任务记录沿用推荐工作台。

生源省份是参加高考的省份。想去的省份是就读地域偏好，两者分别保存。“我想去江苏”只提议修改地域偏好，“我的生源省份是江苏”才提议修改生源省份。

## 前后端流程

1. `POST /api/v1/me/profile/parse` 接收 `{ "text": "我是浙江考生，位次20000，选科物化生" }`，返回 `proposed_changes`、`missing_fields`、`questions`。采用确定性识别，不依赖模型，不自动保存、不自动授权。未识别的信息由用户在表单补充。
2. 用户确认后，`PATCH /api/v1/me/profile` 携带 `expected_version` 保存画像。`score` 允许 `null`，`subjects` 为三门选科；`preferred_regions` 同时容纳意向省份或城市，新增可选 `preferred_schools: string[]` 保存意向院校名称。前端对应 `cities`、`preferredSchools`，专业仍对应 `interests`。省份仍使用 `province_code` / `province`。
3. 保存成功后，`POST /api/v1/recommendations` 使用新的 `profile_version_id`、`intent: "admission"`、问题和 `risk_preference: 50`，并携带 `Idempotency-Key`。基本信息齐全即进入队列，缺少分数或偏好不会进入 `waiting_input`。规则暂仅覆盖浙江 2026 普通类。
4. 抽屉通过已有 `/recommendations/{id}/events` SSE 观察进度，并读取 `/recommendations/{id}`；只有 `validation.status=passed` 的成功或部分完成任务才展示候选。来源与硬条件不明时保留“待确认”，硬条件失败项不进入候选。
5. 用户修改可选偏好后再次点击更新，或确认聊天中的 `profile_update` 信号，系统生成新画像版本并创建新任务。已生成任务继续保留原画像与资料快照，不覆盖历史推荐。

聊天信号支持明确的省份、年份、分数、位次、三门选科、意向地域、专业和院校。例句包括“我想去江苏”“想学计算机专业”“意向院校：某大学”。`POST /chat/profile-signals/{signal_id}/resolve` 仍接收 `decision` 和 `expected_version`，由后端检查归属、版本和重复确认。确认界面显示旧值和新值；拒绝不会修改画像。模型提出的方向不会自动变成用户偏好。

## 推荐排序与边界

地域偏好同时对照院校所在省份和城市。专业、地域、院校名称偏好用于排序，不被当作录取概率。未确认位次口径或没有可比历史时，只展示探索方向，历史风险保持未知。预算、校区、批次和官方选科要求不完整时，结果仍明确标注待核对。初次推荐不虚构用户的偏好，也不把缺失数据补成已满足。

普通聊天优先检索已发布招生计划；没有命中时回退到全国院校名录，只按地区/层次列出学校名称、所在地和办学层次，不把学校与专业兴趣、投档分或录取可能关联。全国名录不含专业、投档分和招生计划，回答会明确说明这一点。

当前普通聊天仍需要配置 OpenAI 兼容模型。结构化画像、规则推荐和确定性文本识别不依赖聊天模型。对话识别是有限语法，不能替代用户核对，也不是任意语义解析。

## 部署自动抓取核查

已有 `crawl-worker`、`maybe_enqueue_startup_crawl` 和全国名录同步。当前默认配置 `sources=[]`、`discovery.enabled=false`、`discovery.auto_start=false`，只同步全国院校基础资料，不再自动抓取浙江招生计划；如需省级数据，必须显式启用 discovery 后由管理员触发。启用后的自动入队还要求模型配置完整、数据库没有活跃招生单位，而且相同配置指纹没有已有抓取记录。失败后不会因重启而对同一指纹无限重抓，可从管理页手动创建新任务。

处理范围包括允许域内官方链接发现、静态 HTML/PDF/XLS/XLSX 抽取、原始资料与证据暂存、管理员批准及后续导入发布。它不会在部署后自动发布未经审核的数据，也不是全国院校数据的一键全量采集。

本次修正首次部署时的启动顺序：构建镜像，启动并等待 PostgreSQL，在一次性 API 容器运行迁移，迁移成功后再启动 API、推荐 Worker、抓取 Worker 和前端。迁移失败时不继续启动新服务，避免抓取 Worker 在数据表尚未创建时耗掉首次启动尝试。完整 Docker 路径仍应在部署机器验证。
