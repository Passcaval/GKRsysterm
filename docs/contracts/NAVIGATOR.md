# 领航员：先推荐，再补充

## 输入与行为

个性化推荐需要生源省份、报考年份、省内位次、三门选科，以及用户同意使用画像。界面默认年份为 2026，用户可以修改。分数、意向省份/城市、专业、院校、预算、位次口径和批次均可后补。画像允许保存草稿，推荐任务只追问缺少的必需项。

领航员抽屉不再提供画像表单。用户直接在对话框里说出生源省份、位次、选科和目标；系统从明确语句中自动整理，并在对话中继续追问缺失的必需项。信息足够后，点击“用对话里的信息生成推荐”即可生成可追溯任务，不需要填写任何表格。没有地域、院校或专业偏好时，先给出可比较的方向与利弊。完整任务记录沿用推荐工作台。

普通问答不要求登录。未登录请求由前端携带最近对话 `history`，后端不创建会话或画像记录；登录用户的消息才会持久化。保存正式推荐任务需要登录，社区发帖需要登录，审核和管理功能需要管理员权限。

生源省份是参加高考的省份。想去的省份是就读地域偏好，两者分别保存。“我想去江苏”只记入地域偏好，“我的生源省份是江苏”才记入生源省份。

## 前后端流程

1. `/api/v1/chat/stream` 在回答前从用户消息中确定性识别省份、年份、分数、位次、完整三门选科、意向地域、专业和院校。识别结果自动合并进新的 `ProfileVersion`，同时写入 `chat_profile_signals` 作为检索反馈和版本审计；SSE `profile_update` 携带 `applied: true`、全局画像和本会话画像，前端立即更新星图与推荐状态。每个会话只使用本会话信号构建对话画像，新会话不会继承其他会话或全局画像中的旧信息；全局画像仍供星图使用。未登录请求不写 `ProfileVersion` 或 `chat_profile_signals`，从 profile_context 和新消息整理临时会话信息；旧客户端仍可仅发送 history。
2. 如果信息还不完整，保存的是草稿：缺失的省份、位次、选科保持为空，`consent` 保持 false；不会用模型推测补齐。`PATCH /api/v1/me/profile` 仍保留给接口和旧客户端，前端不再提供画像填写页。
3. 画像中的省份、年份、位次、三门选科齐全后，对话中的“用对话里的信息生成推荐”按钮会带上用户明确点击授权的 `consent=true`，调用 `POST /api/v1/recommendations`，使用新的 `profile_version_id`、`intent: "admission"`、问题和 `risk_preference: 50`，并携带 `Idempotency-Key`。规则暂仅覆盖浙江 2026 普通类。
4. 抽屉通过已有 `/recommendations/{id}/events` SSE 观察进度，并读取 `/recommendations/{id}`；只有 `validation.status=passed` 的成功或部分完成任务才展示候选。来源与硬条件不明时保留“待确认”，硬条件失败项不进入候选。
5. 用户继续在对话里补充或修改偏好后，系统自动生成新画像版本；重新生成推荐即可使用新版本。已生成任务继续保留原画像与资料快照，不覆盖历史推荐。

`POST /chat/profile-signals/{signal_id}/resolve` 仅保留用于历史待确认信号；新对话产生的信号状态直接为 confirmed，不再弹出确认卡片。模型提出的方向不会自动变成用户偏好，只有用户原话中的明确事实才会写入。

## 推荐排序与边界

地域偏好同时对照院校所在省份和城市。专业、地域、院校名称偏好用于排序，不被当作录取概率。未确认位次口径或没有可比历史时，只展示探索方向，历史风险保持未知。预算、校区、批次和官方选科要求不完整时，结果仍明确标注待核对。初次推荐不虚构用户的偏好，也不把缺失数据补成已满足。

普通聊天优先检索已发布招生计划；没有命中时回退到全国院校名录，只按地区/层次列出学校名称、所在地和办学层次，不把学校与专业兴趣、投档分或录取可能关联。全国名录不含专业、投档分和招生计划，回答会明确说明这一点。

当前普通聊天仍需要配置 OpenAI 兼容模型。结构化画像、规则推荐和确定性文本识别不依赖聊天模型。对话识别是有限语法，不能替代用户核对，也不是任意语义解析。

## 部署自动抓取核查

已有 `crawl-worker`、`maybe_enqueue_startup_crawl` 和全国名录同步。当前默认配置 `sources=[]`、`discovery.enabled=false`、`discovery.auto_start=false`，只同步全国院校基础资料，不再自动抓取浙江招生计划；如需省级数据，必须显式启用 discovery 后由管理员触发。启用后的自动入队还要求模型配置完整、数据库没有活跃招生单位，而且相同配置指纹没有已有抓取记录。失败后不会因重启而对同一指纹无限重抓，可从管理页手动创建新任务。

处理范围包括允许域内官方链接发现、静态 HTML/PDF/XLS/XLSX 抽取、原始资料与证据暂存、管理员批准及后续导入发布。它不会在部署后自动发布未经审核的数据，也不是全国院校数据的一键全量采集。

本次修正首次部署时的启动顺序：构建镜像，启动并等待 PostgreSQL，在一次性 API 容器运行迁移，迁移成功后再启动 API、推荐 Worker、抓取 Worker 和前端。迁移失败时不继续启动新服务，避免抓取 Worker 在数据表尚未创建时耗掉首次启动尝试。完整 Docker 路径仍应在部署机器验证。
